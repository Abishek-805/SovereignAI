# Proposed fixes — source and evidence review

Snapshot: 7 October 2026. This reviews the supplied recommendations against local source and preserved results. It does not promote a production architecture or rewrite frozen benchmark outcomes.

## Main finding

The native adapter already sends `chat_template_kwargs: {"enable_thinking": false}`, `tool_choice: "required"`, `parallel_tool_calls: false`, temperature zero and a 4,096-token output limit. The existing llama.cpp launcher already uses `--jinja`; configured profiles use quantized KV caches and supported flash attention where applicable. These proposed settings are not new fixes for the recorded T10 failure.

The saved T10 trajectories show seven successful tool responses first. Native and Nanobot then reached `finish_reason=length` on call eight: 4,096 completion tokens, 17,084 public-content characters and zero tool calls. Hermes reproduced that response, recovered to a tool call, and then hit another 4,096-token prose response before budget exhaustion. There are 26 saved calls and four length finishes across the three arms.

The failing prose repeatedly claims that reserving two seats against capacity five is valid. It overlooks the preceding four-seat reservation: the aggregate would be six. The independent overflow/atomicity oracle is consistent with shared reservation capacity. The code-generation reasoning missed existing state. Required-tool selection also did not produce an action on these responses. Request flags establish what was requested, not whether the runtime/template strictly enforced it.

The runtime usage fields do not supply a reasoning-token split. That measurement is **unknown**, not zero. The historical logical stream parser retained public content and tool fragments; it cannot reconstruct a missing hidden-reasoning count. Current model-stage wire capture can preserve raw response bodies for a future independent template/stream diagnosis.

Machine-readable audit: `evidence/code-agent-fidelity-v1/reports/t10-generation-audit.json`. It is generated by `experiments/fidelity_v1/audit_generation.py`, which reads saved calls without invoking models or changing their outcomes.

## Review of all supplied recommendations

| Proposal | Evidence-based disposition |
|---|---|
| Disable thinking and force tools | Already enabled. Diagnose template/raw-stream enforcement separately; do not claim toggling the same flags fixes T10. |
| Fixed 150-line files / one-file calls | Not a universal correctness rule. Line counts do not bound tokens, and mechanically splitting modules can impair coherent edits. The existing tools already support targeted patches. |
| Mandatory initial checklist/scratch-file call | Adds a planning step and changes the frozen scaffold. Not applied. Any candidate change requires a separately labeled evaluation rather than altering this comparison. |
| Coder grammar-action fallback | Plausible separately tested adapter candidate. API compatibility is insufficient, but one failing rename does not justify dropping a model after an arbitrary two-attempt rule. |
| Rules-first task routing | Existing advisory rules and task-level ownership already exist. Preserve frozen classifier failures; model quality and switching benefit remain unproven. No router replacement applied. |
| Pin original request | Native immutable request/context retention already exists. Test stale intent against exact call contexts instead of adding duplicate prompt injection. Filename keywords alone are not reliable semantic validation. |
| Roll back deleted public symbols | Behavior preservation matters, but legitimate rename/removal can change public symbols. An unconditional AST veto would reject valid tasks such as T01/T02. Independent properties and request-scoped authorization are safer than a blanket symbol rule. |
| Require runnable build contract | Existing build/runtime validation provides scoped support. HTTP start alone cannot prove the requested API, validation and storage behavior. Avoid a mandatory planner stage or app-specific scaffolds. |
| Larger pinned dependency image/wheelhouse | Existing image includes demonstrated Flask dependencies. Expanding packages requires image/policy re-attestation and matching evaluation conditions. Missing dependencies remain explicit BLOCKED conditions. |
| Port polling / warm preview container | The documented Flask adapter executes WSGI requests in Docker without exposing a listening port. Port polling is inapplicable there. Persistent-container performance work would require separate lifecycle/isolation validation. |
| Server-owned state / heartbeat / TTL release | Implemented passive experiment liveness only. Automatically releasing production locks on a missed heartbeat is unsafe while work may still be running. UI/SSE changes require actual backend/job inspection and browser acceptance. |
| Structured templates, coverage and thresholds | Verified computed results and fallback presentation already exist. Coverage and intent validation still matter. Comparisons can involve several students/tests, not necessarily two cohorts. Follow-up thresholds may be explicitly authorized by conversation; never inheriting them would break legitimate follow-ups. |
| Windows publication checks/journal | Existing revision/path checks and journal are retained. The source documents remaining race limits; no unsupported claim that races are impossible to eliminate or now eliminated. |
| RAM/VRAM measurements | Still pending representative model evaluation. Whole-GPU VRAM includes display use; flag/configuration presence is not measured viability. |
| Resume interrupted experiment | Missing-cell continuation already exists. Passive liveness now distinguishes checkpoint from activity. Do not change T10 prompts/kernel and then silently merge new outcomes with the frozen comparison. |
