# Knowledge, context routing and workbench reconstruction

2026-09-28. This report supersedes the earlier Read/Ask Knowledge layout reports. Production Svelte components remain connected to the existing backend; the isolated HTML concept is labelled sample data.

1. **Architecture.** Chat, Agent, Code, Knowledge, Control Center. Knowledge imports, searches, previews and manages documents; it has no assistant or composer.
2. **Design decision.** A separate five-surface concept was built and compared with the supplied screenshots. Adopted labelled collapsible navigation, a compact header, neutral charcoal/teal tokens, paired light theme, and task-specific layouts. See [comparison](design-comparison.md).
3. **Preserved mechanics.** Existing Svelte/Bits/Monaco, conversation persistence, model controls, real task events, sandbox, download endpoints, keyboard navigation and applied-code review remain in use. No framework replacement.
4. **Context connection.** Chat and Agent connect existing document IDs through a searchable picker. Context chips open the original Knowledge destination or disconnect. Uploaded files remain a separate action; selected scope does not grant mutation permission.
5. **422 repair.** Code sends four successful recent turns within the eight-entry API limit. Failed/cancelled turns are excluded. FastAPI field validation is now readable across Code, Agent and Knowledge requests. Overlong Agent/Code goals retain the draft.
6. **Interpretation before tools.** The local model chooses conversation, document search/report, code inspection/edit or calculation before project reading. No greeting response dictionary. Short conversational responses use one inference; detailed responses receive the larger conversation output budget.
7. **Connected relevance.** Connected document names are reference metadata. Related questions retrieve scoped evidence. Unrelated conversation answers without opening documents or project files. Ordinary Chat no longer silently injects library-wide RAG or eagerly loads embeddings.
8. **Overview/report coverage.** The planner distinguishes focused questions from collection overviews. Overviews offer balanced complete passages from each selected document under measured tokenizer admission. Coverage names represented/omitted documents and indexed passages. Word reports append deterministic coverage disclosure; Chat can return Word downloads directly.
9. **Stop.** Code queues Stop during admission against the new job, avoiding stale IDs. Chat registers cancellation before asynchronous persistence and queues Stop if admission is underway. Backend checks cancellation after planning and before publishing answers. The pinned stream API now receives request-owned GET/DELETE and conversation identity headers.
10. **Stop limitation.** Runtime stream eviction is not guaranteed to interrupt its underlying inference immediately; non-streaming jobs also finish their current inference call before observing cancellation. No global slot cancellation is used. See [backend audit](backend-routing-audit.md).
11. **History and evidence.** User turns persist during work. Existing document assistant history migrates idempotently into normal Chat, retaining original local data on migration failure. Citations open the original document/page/indexed passage. Source text is available for inspection, and coverage persists with answers.
12. **Knowledge preview.** Original PDFs use the browser viewer. Other supported documents expose extracted indexed text and original download. Metadata shows actual indexing/extraction/current content hash, not fabricated file sizes or version timelines. The shell does not scroll; long library/preview content scrolls locally when necessary. Mobile switches list/preview without removing controls.
13. **Code/terminal.** Monaco and review controls remain functional. The terminal accepts typed program input at the active surface and isolated shell commands. It is Docker Linux, not host PowerShell and not a persistent host PTY. Assistant edits are applied before review; Accept keeps them and Undo restores the previous file.
14. **Models and routing.** Installed text and vision baselines remain. Friendly labels expose technical IDs in details. No untested coding model was downloaded. Model-centric candidate selection, measured resource admission, CPU router deployment and broad quality/performance release gates remain unfinished; the current route labels must not be mistaken for those completed gates.
15. **Automated validation.** Backend regression: 241 passed, six skipped. Svelte: zero errors/warnings. Final build/frontend/browser validation recorded below when complete. Skipped tests are not counted as success.
16. **Live validation.** Installed-model HTTP acceptance: hi, hay, whats up, identity and prime-number questions answered through conversation with connected Knowledge and a selected project, without file-reading stages or project mutation. Two-document overview synthesized actual SOP/inspection evidence and represented both documents. These are smoke checks, not statistical router accuracy or latency claims.
17. **Remaining improvements.** Evaluate model-specific coding candidates and router quality/cost on independent tasks; improve long-document map/reduce beyond excerpt overview; add persistent isolated PTY sessions if required; test extraction and vision against independently checked fixtures. No claim of perfect model answers, complete original-file interpretation, or proven speed improvement.
