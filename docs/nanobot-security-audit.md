# Nanobot source audit: tools, permissions and execution

Research Phase A only, 2026-10-03. Upstream: https://github.com/HKUDS/nanobot, pinned commit `432421bceba6e50ec435924c7b21ef341ed69e55`, inspected checkout `C:/Users/ashek/AppData/Local/Temp/sovereign-nanobot-audit-20261003`. No upstream application, tests, installers or generated commands were executed. Findings describe inspected source, not an independently demonstrated exploit or security certification.

## Decision

Adapt small tool-contract and process-lifecycle ideas. Do not import Nanobot's execution backend as SovereignAI's security boundary. Its Windows shell path explicitly runs unsandboxed when a sandbox is configured. Its supported Unix wrappers permit networking and write directly to the real workspace. Keep SovereignAI's existing single-heavy-model lease, Docker isolation, bounded repair, staged review and explicit Accept publication.

## Existing Sovereign boundaries to preserve

Current local `router/sandbox.py`: `SANDBOX_POLICY` L62–67 selects Docker Linux, network none, non-root UID 65534, read-only root, isolated mounts, one CPU and 512 MB. `Sandbox.execute` L138 onward rejects unsupported/unready backends; Docker invocation L173–181 applies network isolation, all capability removal, no-new-privileges, PID 64 and fixed memory/swap/CPU budgets. Execution checks cancellation L200, kills the named container on timeout/cancel, and removes it in `finally` L237–244. These references describe present source; upstream was not run to compare measured isolation.

Current local `workflows/coding_workspace.py`: `_file` L254–263 rejects symlink/junction escapes; `_stage_changes` L500–535 stores expected revisions and draft bytes; `accept` L549–599 validates current revisions and staged hashes before `_publish_changes`; `validate_staged` L601–655 executes exact staged bytes and checks workspace stability. Publication recovery/journaling is in `_recover_publications_checked` L82 onward and `_publish_changes` L143 onward. Tool success, model completion or a file write must never replace these checks.

## Tests inspected, not executed

- `tests/security/test_workspace_policy.py` L34–160: traversal variants, sibling-prefix paths, symlink escape, extra roots, exact files and link escape.
- `tests/tools/test_exec_security.py` L32–740: private URL filtering, explicit full-access guard skipping, working-directory escape, redirection, command substitution, bind roots and path-token edge cases.
- `tests/tools/test_sandbox.py` L17–494: wrapper argument/profile construction, parent masking, read-only binds, quote escaping and unsupported backend errors. Construction assertions alone do not prove kernel enforcement on this Windows laptop.
- `tests/tools/test_shell_reap.py` L119–400: timeout/cancellation and descendant cleanup, including some real POSIX process tests. Platform-specific coverage is not automatically Windows coverage.
- `tests/tools/test_exec_session_timeout.py` L18–109: hard timeout without polling, completed output retained, and configured zero timeout permitting longer runs.

## Limits and recommended scope

This is a static, bounded review of tool execution and selected tests, not a whole-repository penetration audit. No upstream tests were run, no sandbox escape was attempted, no model quality gain was measured, and no production/harness changes were made. MCP, channel authentication and full remote-service attack surfaces require separate review before any import. No reviewed component provides evidence that an installed model universally understands all tasks.

The safest small integration candidate is exact tool identity plus schema validation, bounded argument-envelope repair and structured real execution feedback through the existing supervisor. Session-owned cancellation cleanup is useful when adding persistent helper sessions. Implement only after a measured gap is identified and local regression tests establish unchanged workspace authority, Docker isolation, one-heavy admission and Accept behavior.
