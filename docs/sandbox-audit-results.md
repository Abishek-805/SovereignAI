# Sandbox remediation evidence — 2026-09-30

> Historical checkpoint. Counts, publication limitations and browser results below describe an earlier run and are superseded where newer evidence exists in [final release report](final-release-report.md), [publication architecture](publication-architecture.md) and [sandbox threat model](sandbox-threat-model.md). Do not use these historical counts as final release PASS evidence.

The staged publication path was exercised by backend tests: before Accept and after Discard the canonical bytes stay unchanged; stale revisions block Accept and retain the draft; Docker-unavailable drafts cannot publish; Accept writes only planned paths; an injected failure on the second path rolls back the first. The full backend suite passed with 548 tests, seven skipped, and one Starlette deprecation warning. Frontend unit tests passed: 714 across 58 files. Frontend check passed with zero errors and warnings, and the production build completed successfully.

The pinned workbench image was live-tested on Docker Desktop's Linux engine with 18 verifier checks passing: normal execution, network denial, read-only root and inputs, unprivileged user, no capabilities or privilege escalation, PID/memory/CPU controls, bounded output tmpfs, absent Docker socket and dummy host environment/secret values, timeout, cancellation, and container cleanup. A controlled output-filling program reached the 384 MiB tmpfs limit after 48 files of 8 MiB; the container was removed. Additional live temporary-project checks passed: moving an HTML file into an existing folder with Docker validation and Accept; generating/validating two Java search files in an existing folder before Accept; and running the actual Qwen 4B planner and code generator on both user-reported requests. Qwen planned the web moves, including replacement of an existing destination after review, and the coding workflow repaired its mistaken edit actions on absent Java targets before Docker validation. These tests used temporary inputs, not user projects.

The browser UI suite ran after installing its pinned Playwright Chromium: 31 tests passed and four failed across three existing stories (one Markdown math timeout, one Sidebar navigation assertion, two Chat form accessibility assertions). The local backend was stopped, causing proxy errors during the run. The client suite could not start before installation because Playwright's Winldd executable was missing; after installation, Chromium launch failed with `spawn UNKNOWN`. These are not passes for browser acceptance of the changed publication flow.

This is not a security certification. The release gates for crash-atomic multi-file publication and cross-process race resistance remain **not met**. Agent file organization now stages changes for reviewed publication; focused tests cover existing folders, binary files, destination collisions, and stale revisions. Manual IDE/terminal writes are a separate user-driven path. See [boundary details](sandbox-boundary.md) and [threat model](sandbox-threat-model.md).
