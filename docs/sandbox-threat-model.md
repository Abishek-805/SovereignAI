# Sandbox threat model

Untrusted inputs are model-generated source, user-entered project source, stdin, terminal commands, project filenames, and generated outputs. A malicious program may try to read host secrets, cross into another project, exhaust disk/CPU/memory/processes, contact the network, or escape the container. The expected trust boundary is a temporary Docker Linux container with one read-only input tree and one bounded writable tmpfs. The backend is trusted and remains a higher-value target; compromise of Docker Desktop, the Linux kernel, or backend process is outside the runner's enforceable guarantees.

The input mapper validates relative paths and excludes common secret paths such as `.env*`, `.git`, cloud credentials, private keys, and SSH directories. This is defense in depth; it is not a general secret scanner. Output collection accepts a small fixed set of top-level files. Canonical publication is a separate backend action following validation and revision checks. The UI must not treat an unvalidated draft as saved project code.

Residual risks include an external writer racing publication, power loss during multi-file publication, symlink/junction swaps by an actor with filesystem access, resource consumption by Docker itself, and unrecognized secret filenames inside an explicitly selected project. Docker `--network=none` prevents container network access in the verified configuration; it does not prove there are no container escape vulnerabilities. Manual Code file operations, terminal synchronization, project administration, and Knowledge mutations have separate scopes.
