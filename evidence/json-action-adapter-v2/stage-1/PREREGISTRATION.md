# Stage 1 preregistration — JSON action adapter

## Scope
Only Stage 1; no generated action dispatch, candidate execution, publication or production modifications. Stage 0 and recovery evidence remain frozen.

## Subtests / hypotheses
1. Compatibility: one request with minimal object schema requiring ok=true, then one identical request adding the first frozen registered native tool and tool_choice=auto. Independent variable: native tools alongside response_format. Freeze model/runtime, prompt, thinking=false, temperature=0, max_tokens=4096. No seed supplied, as baseline. Accept HTTP success and a completed schema-valid response; distinguish HTTP acceptance from constrained generation. If json_schema is rejected, one GBNF fallback using the same schema is allowed. Stop if neither mechanism works. No retries to improve valid cells.
2. Schema extraction: deterministic conversion of every frozen native ToolRegistry action to a tagged action {name, arguments}; preserve parameter schemas. No model output is used in deriving schema. Finish is the existing finish action with empty parameters. Verify parser-to-existing-registry check compatibility without execute/dispatch.
3. Fidelity: for every action, one valid representative plus unknown name, missing required argument, wrong type and forbidden extra-key cases where applicable. Independent variable: argument validity. Registry.check is the control. No tool executes. Keyword support is audited against pinned b11132 converter source, not assumed from schema validity. Stop on semantic loss or unresolved fidelity.
4. String bounds: inspect all preserved independently successful baseline cells in the 15-task fixed-Qwen runner comparison (native/nanobot/hermes). Include every recorded emitted tool argument in those successful trajectories, retain exact largest value and path. Derive every unbounded string maxLength = largest observed character count + 256 characters. Margin fixed before model outputs. Missing field observations mean UNKNOWN and block fidelity; do not invent bounds or remove actions. Bounds cover the observed benchmark scope, not arbitrary future requests.
5. Size: compute JSON structural overhead and worst escaped size (up to six ASCII characters per BMP code point, twelve per supplementary code point with ensure_ascii). Measure concrete schema-valid Unicode/escape stress objects with the actual runtime tokenizer. If any legitimate benchmark-relevant bounded action needs more than 4096 output tokens, stop SCHEMA/ACTION-BUDGET INCOMPATIBILITY. Do not shrink bounds or increase output budget. Passing a stress sample alone does not prove a universal upper bound.
6. Exact replay, only if earlier gates pass: reuse preserved Arm A; new Arm B action-only and Arm C state+action, one temperature-0 call each, seed absent. Remove native tools/tool_choice, add response_format only; retain all messages, observations, parallel_tool_calls=false, max_tokens=4096, thinking=false and runtime settings. State bound fixed at 512 characters. State is model-written, never injected/corrected. Save exact request diffs. No control rerun unless current-session mismatch requires it, recorded as amendment before execution.

## Success/disproof and analysis
Record emission, parseability, registered name, schema-valid args, semantic correctness and state correctness separately. Valid JSON never establishes task correctness. No oracle executes. Unsupported mechanism, schema/final-action fidelity failure, budget incompatibility, conflicting evaluator/generation or lost readiness stops execution. Separate observed/inferred/unknown conclusions. Stop after report and await approval before Stage 2. Preserve raw requests/responses/headers and errors even when normalization or transport fails. All analysis and runtime calls are sequential.

## Sample size and evidence
Two compatibility cells; at most one same-schema fallback if needed. Deterministic finite schema cases for every action. All available independently successful baseline trajectories, with explicit coverage gaps. One stress sample per bounded action plus escaped-size calculations. At most two new replay cells after gates. Evidence under stage-1/compatibility and the unique execution directory. No preregistration edits after execution; amendments are separate.
