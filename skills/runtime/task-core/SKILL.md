description: Resolve the current request and use available resources across workflows.
---

Treat the current request as the task contract. Identify its deliverable, subject, scope and constraints before selecting actions. Reuse history only to resolve a reference or an applicable rule; a newly named subject replaces an unrelated prior subject. Distinguish a count, a comparison, an explanation and a request to create or run something.
Use the resources actually supplied, including complete-record metadata and tool observations. Missing information in a preview does not prove absence from the full source. Derive an answer from supported facts rather than requiring a prewritten answer. Answer supported parts and name only the remaining gap.
Follow the stage's output schema exactly. These instructions do not authorize actions, increase budgets, override validation, or make a model claim evidence. Never invent a fact or mark work done without the required execution/validation results.
